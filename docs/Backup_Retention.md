# Reviewed backup retention

Open Backups and recovery > Storage and backup cleanup. Storage used includes the private managed backup namespace and small record Undo history. Full snapshot allowance remains a conservative 12-job / 2 GiB safety ceiling; shared originals are counted per snapshot for that allowance, while actual storage reports deduplicated bytes. Large usage listings explicitly report an incomplete lower bound rather than pretending to be exact.

The newest seven normal checked backups are kept by recommendation. Select other eligible snapshots and choose Review cleanup. The preview names the exact snapshots, reports retained snapshots/shared files and estimates unshared original bytes to reclaim. Approve cleanup is a separate explicit action. No automatic pruning is enabled. The newest checked recovery point and newest checked normal backup cannot be selected. Protected pre-change points stay protected until an owner reviews the specific point, confirms its protected changes were verified and another newer checked point exists, and releases its protection. Release does not delete it; reviewed cleanup remains separate. Released points cannot be used to protect future bulk imports.

Incomplete and failed snapshots are not silently discarded. Selecting them requires an explicit acknowledgement that no pending action needs those jobs. Retained incomplete snapshots still pin all original hashes in their captured manifests. Unknown/corrupt retained references stop cleanup rather than risk losing a recovery copy.

The server rechecks the preview fingerprint under a backup-store lease. Once approved, the persisted cleanup blocks competing full-backup creation/progress, bulk import application and whole-catalog restore. Live ordinary record edits remain quick and available. Selected snapshot metadata is removed in bounded groups; unreferenced content-addressed backup originals are removed in bounded groups of sixteen. Shared hashes required by any retained job remain. Live attachments, D1 rows, record Undo history and all other namespaces are outside the deletion scope. The approved job can resume after an interrupted request or closed browser; the minute cron advances running jobs. Failed jobs pause for owner review/resumption. Completion receipts remain private, and the completed control record is compact.

A short conditional R2 lease serializes backup-store mutations, renews before writes during long operations, and rejects competing callers. A superseded expired lease cannot resume mutations without a successful renewal; the timeout is fifteen minutes and cooperative bounded batches remain far below it. A prior complete restore must finish before cleanup; an active or interrupted restore protects all recovery state. Preview fingerprints and exact object etags reject stale approvals or unexpected object changes. New retained references cannot be introduced during an approved cleanup because managed-store writers and import apply share the lease/cleanup gate.

The metadata/control/copy-plan changes are private R2 JSON and introduce no D1 migration or new paid resource. Original-content checksums, full backup formats, the prior Windows helper and manual off-provider archives are unchanged. This is same-provider retention, not an independent disaster-recovery copy. Real removals remain an owner-reviewed operation; local synthetic tests exercise reclamation without pruning real backups.
