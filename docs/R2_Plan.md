## Product acceptance versus shipping

An R2.1 development product milestone may be demonstrated while a production-release blocker remains open; it must be labeled **development acceptance only**, not released. Missing safe photo activation prevents the complete R2.1 product checklist passing. Unresolved CC-TODO-019 prevents production promotion even if all UX scenarios pass.

Every phase that changes schema/storage must keep archive validators, independent original checksums, migrations, restore profiles and compatible code rollback together. Never automatically restore D1/R2 data during ordinary code rollback. Known active/failed/unknown restore, backup, import or retention work stops release. No lease expiry, fixed sleep or healthy endpoint alone proves drain or permits unlock. Retain the approved proportionate KISS settling process for compatible releases; initial R1 visibility limits and residual risk must be explicit. Neither migration 0005 nor a future Sets schema is silently treated as a schema-free routine release.

Full automation is an R2.3 outcome; **safe release controls remain earlier gates**. If an earlier production release is desired before complete automation, the owner must separately approve a concrete supervised execution procedure satisfying those controls. This proposal does not substitute a manual production path for the approved release interface or waive any safeguard. If no adequate procedure is approved/proven, the earlier release stays blocked.
